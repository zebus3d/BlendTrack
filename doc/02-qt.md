# 02 - Qt: los conceptos que usa el proyecto

Esta es la parte que más cuesta al empezar. Aquí tienes cada concepto de Qt
Widgets (PySide6) que aparece en el proyecto, con **dónde verlo** en el código.
No hace falta memorizarlo: vuelve aquí cuando te pierdas.

## 1. Toda la interfaz es Python

A diferencia de Kivy, en Qt no hay lenguaje declarativo: los widgets se crean y
se montan desde Python. Lo que sí hay es una **hoja de estilos** (QSS, un CSS
recortado) que se aplica de golpe a toda la aplicación:

```python
app.setStyleSheet(qss.build_qss())      # main.py
```

La separación que buscamos con esto es:

- `ui/qss.py` → **cómo se ve** (colores, bordes, tamaños, hover).
- `ui/widgets/*.py` → **qué hace** (lógica y señales).

En este proyecto: la clase `Pill` está en `src/ui/widgets/buttons.py` y su
aspecto en la regla `QPushButton#Pill` de `src/ui/qss.py`.

## 2. `objectName`: cómo el QSS encuentra cada widget

El QSS no sabe de clases de Python, así que se selecciona por `objectName`:

```python
meta.setObjectName("Muted")             # ui/widgets/cards.py
```
```css
QLabel#Muted { color: {t.MUTED}; }  /* en qss.py, con el color del tema */
```

Regla práctica: **si añades un widget con aspecto propio, dale un `objectName` y
añade la regla al QSS**. No pongas colores con `setStyleSheet` sobre el widget:
se escapan del tema.

Para variantes dentro del mismo widget se usan **propiedades dinámicas**:

```python
self.setProperty("zebra", "true" if zebra else "false")
```
```css
QFrame#Card[zebra="true"] { background-color: ...; }
```

No hace falta repintar a mano: vale con poner la propiedad **antes** de que el
widget se muestre (el primer *polish* del estilo ya la lee).

## 3. Señales y *slots*: los eventos

En vez de `bind()`, Qt usa **señales**: un widget emite y tú conectas.

```python
action.clicked.connect(lambda: self.action_clicked.emit(self.build))
```

Las señales propias se declaran como atributos de clase:

```python
from PySide6.QtCore import Signal

class BuildCard(...):
    action_clicked = Signal(object)   # la build
    notes_clicked = Signal(object)    # la build
```

La tarjeta no llama a la ventana: emite. `MainWindow` (en sus mixins, p. ej.
`build_lists.py`) conecta esas señales con sus métodos (los *slots*). Así la
tarjeta se puede probar sola.

## 4. Hilos: `WorkerBridge` y las señales

Lo lento (red, disco) va en un hilo aparte y vuelve al hilo de la interfaz
**emitiendo una señal**, nunca tocando widgets desde el hilo:

```python
class WorkerBridge(QObject):            # ui/widgets/shell.py
    progress = Signal(int, int)
    done = Signal(str)
    error = Signal(str)
```

Míralo en `install_build` / `_on_download_done` de
`src/ui/widgets/downloads.py`. **Nunca toques un widget desde otro hilo.**

## 5. Layouts: cajas que reparten el espacio

No hay coordenadas: se anidan layouts.

| Layout | Para qué |
|---|---|
| `QVBoxLayout` / `QHBoxLayout` | una columna / una fila |
| `QGridLayout` | rejilla (la tienda en modo cuadrícula) |
| `QStackedWidget` | una vista a la vez (Tienda / Instaladas / Ajustes) |

```python
lay = QVBoxLayout(self)
lay.setContentsMargins(14, 14, 14, 14)   # margen interior
lay.setSpacing(6)                        # separacion entre hijos
lay.addWidget(logo)
lay.addWidget(title)
lay.addStretch()                         # empuja lo de arriba hacia arriba

row = QHBoxLayout()
row.addWidget(launch, 1)                 # el 1 es el "stretch": se come el hueco
```

- El **stretch** decide quién se estira cuando sobra sitio. El pie de la app lo
  usa para dejar el zoom pegado a la derecha.
- `setFixedHeight` / `setFixedWidth` para lo que no debe cambiar (tarjetas de la
  rejilla, barra lateral).
- Ojo: un widget **oculto no aporta su stretch**. Por eso el progreso y el zoom
  viven cada uno en su contenedor (`progress_box`, `zoom_box`): así el zoom
  queda a la derecha tanto si hay descarga como si no.

## 6. El patrón de las tarjetas (y el hover)

`_HoverCard` (`ui/widgets/cards.py`) marca una propiedad dinámica al entrar y
salir el ratón:

```python
self.setAttribute(Qt.WA_Hover, True)
self._set_hover(True)                   # setProperty("hover", "true"|"false")
```

Hace falta porque `QFrame#Card:hover` **no basta**: cuando el ratón está encima
de un hijo (una etiqueta, un botón), el padre puede no recibir el estado hover.

Y cuidado con la **especificidad del QSS**: `#Card[installed="true"]` y
`#Card:hover` empatan, y gana la que va más abajo. Por eso los `:hover` están al
final del bloque en `qss.py`; si no, las tarjetas instaladas nunca se resaltan.

## 7. Colores y tamaño de letra del tema

Los colores están en `ui/theme.py` y el QSS los interpola con f-strings
(`{t.ACCENT}`). **No se escribe un color a mano** en `qss.py` salvo que sea un
tono derivado de un token (por ejemplo el hover de un botón).

El tamaño de letra base lo fija el QSS (`QWidget { font-size: ... }`, con
`theme.FONT_SIZE`, que hoy vale 13), y **pisa
cualquier `setFont`** que hagas desde Python. Si un icono o un texto tiene que
ser más grande, se hace con una regla QSS, no con `setFont`.

## 8. `QDialog` propio en vez de `QMessageBox`

`QMessageBox` coge el estilo claro nativo y desentona. En `ui/widgets/dialogs.py`
heredamos de `QDialog` (`AppDialog`) y montamos los botones con `CardButton`, así
el QSS de la app se aplica solo. `confirm()`, `show_error()` y
`update_available()` son atajos para los tres casos típicos.

## 9. Efectos: la sombra del logo

Qt trae `QGraphicsDropShadowEffect`, que es el `drop-shadow` de CSS: repinta el
widget a un pixmap y lo difumina. Está en `logo_shadow()` (`ui/widgets/cards.py`)
y se aplica al logo de la cabecera y al de las tarjetas.

Dos cosas que hay que saber:

- **Solo se puede poner UN efecto por widget.** Si un widget necesita dos (p. ej.
  sombra + opacidad), hay que combinar uno de los dos a mano. Es justo lo que
  pasa con las builds no instaladas: como el `opacity` del QSS no hace nada
  sobre un pixmap, la atenuación se pinta en el propio pixmap
  (`_with_opacity`) y el efecto queda libre para la sombra.
- El efecto se recalcula cuando cambia el widget de origen, no en cada pintado,
  así que el coste es el de la primera pintura (medido: inapreciable aquí).

## 10. El plugin *offscreen*: probar la UI sin pantalla

Qt puede montar la interfaz sin servidor gráfico, que es lo que usan los tests y
`packaging/capture_docs.py`:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -t . -s tests
```

**Tiene que estar fijado antes de crear `QApplication`** (por eso va en el
entorno del comando). Si se crea antes, Qt elige el plugin por defecto y falla
sin display. Para capturas: `window.grab().save("x.png")` (no depende de GL).

## 11. Trampas que ya están resueltas

- **`deleteLater` no borra en el acto**: si sacas tarjetas de un layout con
  `takeAt`, siguen pintándose en su sitio hasta que el bucle procesa el borrado,
  y durante un frame se ven las viejas debajo de las nuevas. Por eso
  `clear_layout` (`ui/widgets/layouts.py`) hace `setParent(None)` antes de
  `deleteLater`.
- **Reconstruir la rejilla en cada tick de un slider** parpadea y es lento (crea
  y destruye widgets). El zoom usa un *throttle*: refresca como mucho cada 80 ms
  mientras arrastras y guarda el ajuste cuando paras.
- **No dupliques los filtros de `services/`**: usa `api.filter_builds` e
  `installed.filter_installed`. Reimplementarlos en la UI ya causó dos bugs (los
  canales no filtraban ni en la tienda ni en Instaladas).
- **`shiboken6` no se puede excluir** del PyInstaller: sin él el binario falla al
  arrancar (`No module named 'shiboken6.Shiboken'`) y el `--smoke` no lo pilla,
  porque no importa Qt. Prueba siempre la GUI empaquetada.
